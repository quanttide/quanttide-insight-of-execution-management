# 周会是法人记忆的消费场景

周会是法人（公司）以自己的记忆为对象、按周做一次「看清」——它是法人记忆最自然的消费节奏，也是对「看清」的第一条验收。

## 机制

- 记忆要**被定期消费才有价值**：法人记忆的可见性在「周」这个粒度上最有效——粒度太长，记忆失真；粒度太短，只剩噪音。
- 周会 = 法人对自身记忆的**巡检**：谁在推进、哪件事卡住、要不要上升，都从记忆里读，而不是从每个人嘴里问。
- 周检**天然承载职责接棒**：评审 / 验收在周会这个时刻被显性化，是「分配与评审闭环」落到节奏上的那一步。
- 周会是对「看清」的**验收**：能直接读出本周进度，系统才真正成为法人记忆的载体，而不是一套漂亮的看板。

## 迁移

- **产品**：把周会「讲进度」改成「读系统」——周会前看板即进度，不再需要人整理一份周报。
- **服务端**：周检作为「看清」面向治理节奏的对外消费入口。
- **后续阶段**：周会从「只读进度」演进到「在周会上完成评审 / 接棒」——它是职责闭环的落地场景。

## 边界

- 不是把周会搬进系统，而是让周会成为**系统记忆的消费者**——周检是校验，不是功能。
- 周会只解决「看清 / 对齐」。权限、指派、提醒属于**后续自然人阶段**，不在法人阶段的周会里做。
